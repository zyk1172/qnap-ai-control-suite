# v0.3.2 到 v1.0.15 对比

本文以仓库中 v0.3.2 的 MCP 工具表、QPKG 默认配置和 API 路由为基线，对比 v1.0.15。它描述已实现的能力，不把尚未验证的 QTS 私有命令写成已支持功能。

## 执行层

| 项目 | v0.3.2 | v1.0.15 |
| --- | --- | --- |
| 文件根目录 | `/share` | `/`，并在解析符号链接后检查边界 |
| 可执行文件 | 7 个 allowlist：`df`、`ps`、`uname`、`getcfg`、`ifconfig`、`qpkg_cli`、`uptime` | `full_trust` 下任意 argv |
| Shell | 禁用 | `nas_shell` 支持明确 shell、脚本和 pipeline |
| 命令结果 | 部分非零退出可被当成普通结果 | 非零退出、超时、找不到 executable 和启动失败均有明确错误语义，同时保留 stdout/stderr/exit code |
| 命令输入 | 基础 argv | cwd、环境变量、base64 stdin、dry run、输出大小上限 |
| 长操作 | 无通用生命周期 | Job start/list/get/logs/cancel，日志分页且有行数与字节上限 |

这意味着 Agent 不再只能执行预定义诊断命令。任意尚未形成专用工具的 NAS 本机操作仍可通过 `nas_exec` 或 `nas_shell` 完成，并写入审计日志。

## MCP 与文件管理

v0.3.2 有 35 个 MCP 工具，集中在健康检查、系统概览、基础文件操作、QPKG 与 Docker。v1.0.15 有 97 个工具，其中兼容别名仍保留以避免旧自动化失效。

文件能力从文本导向读写扩展为：base64 二进制 range read/write、append、目录与路径管理、copy/move/rename、archive/extract、checksum、tail、search、du、hardlink 和 symlink。递归 chmod/chown 不跟随子目录符号链接。

## Docker 与 Container Station

旧版能列举和操作容器，但创建、删除等调用受 bridge 确认逻辑限制，且对 QNAP Container Station wrapper 的发现较弱。

v1.0.15 会探测 QNAP 的 Docker wrapper，包括 `system-docker` 与 `.libs/docker`。除 `nas_docker_info`、containers、images、inspect、logs、stats 以外，还提供通用 `nas_docker_command`、Compose、network、volume、run/create/remove/exec/pull，以及从 inspect 重建可审阅运行参数的工具。build、pull、Compose 和其他长操作可交给 Job。

## QPKG 与服务

v1.0.15 使用 QTS 实际支持的 `qpkg_cli --start`、`--stop`、`--enable`、`--disable`、`--status`、`--manually`、`--url` 等参数。清单同时保留 qpkg.conf、CLI 结果、安装脚本、`/proc` 运行状态和 PID 证据。

QPKG 启动脚本还处理升级中的遗留进程：仅匹配自身二进制的完整命令行，结束 PID 文件丢失的旧 Agent 后再启动新版本，且不会将被复用的 PID 当成 Agent。

## NAS 管理覆盖

v1.0.15 新增或扩展以下领域：

- 系统资源、CPU/swap、socket、NTP、硬件传感器、进程信号、服务动作和电源动作。
- 磁盘、SMART、mdraid 健康与 scrub、ZFS pool/volume/snapshot，以及 QTS snapshot capability。
- 网络接口、路由、DNS、bridge/bond/VLAN 发现和临时 Linux 网络变更。
- 本地用户、用户组、共享目录、POSIX ACL、NFS export、日志与 NUT UPS。
- X.509 证书元数据检查。

## QTS 私有接口的边界

Virtualization Station、HBS 3、iSCSI/LUN、证书替换、Virtual Switch、持久化系统设置、固件、通知和 Storage Manager 都有 MCP adapter 入口，但 QNAP 的私有 CLI/API 会随 QTS 版本变化。

因此必须先运行 `nas_qnap_probe`，在 NAS 上收集实际可执行路径，再把验证后的绝对 argv 模板写入 `qnap_adapters`。`nas_qnap_ecosystem` 会明确报告 adapter 是否已配置。未配置时，使用 `nas_exec` 或 `nas_shell` 检查 NAS 本机帮助信息；项目不会凭猜测执行私有命令。

## 已验证状态

在 amd64 QTS 设备上已验证：v1.0.15 QPKG 注册和启动、`full_trust` 权限、任意 argv、shell、Container Station wrapper、Docker 信息和硬件温度读取。实际可用的 VM、HBS、iSCSI、固件和其他 QTS 私有 adapter 仍以每台 NAS 的 probe 结果为准。
